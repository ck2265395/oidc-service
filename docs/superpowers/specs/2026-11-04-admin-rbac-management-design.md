# 管理员固定角色与账号管理设计

## 目标

运营后台增加管理员列表、创建、启停、角色调整、密码重置和本人修改密码能力，并以固定角色在后端执行权限控制。

## 角色与权限

- `super_admin`：全部后台能力，可管理管理员。
- `operator`：查看后台数据并执行开发者、应用和应用组审核，不能管理管理员。
- `auditor`：只读查看概览、审核数据、操作审计和统计。

既有管理员迁移为 `super_admin`，本地默认管理员也是 `super_admin`。前端根据角色展示入口和操作，但后端守卫是最终权限边界。

## 管理规则

- 只有 `super_admin` 可以创建管理员、启停账号、调整角色和重置密码。
- 管理员不能停用自己或修改自己的角色。
- 系统始终至少保留一个启用的 `super_admin`；状态与角色变更在事务内校验。
- 创建和重置密码时由服务端生成临时密码，仅在成功响应中返回一次，并设置 `must_change_password=true`。
- 登录后若必须修改密码，只允许访问会话、退出和本人修改密码接口；修改成功后撤销该管理员的其他会话。
- 密码散列和会话标识不进入列表响应、审计详情或日志。

## API 与界面

- `GET /api/v1/admin/administrators`：管理员列表。
- `POST /api/v1/admin/administrators`：创建管理员并返回一次性临时密码。
- `POST /api/v1/admin/administrators/:id/status`：启用或停用。
- `POST /api/v1/admin/administrators/:id/role`：调整固定角色。
- `POST /api/v1/admin/administrators/:id/reset-password`：生成一次性临时密码。
- `POST /api/v1/admin/password`：本人修改密码。

运营后台增加“管理员管理”页面；超级管理员可执行全部管理操作，其他角色不显示该菜单。会话响应包含当前管理员角色及是否必须修改密码。需要修改密码时控制台展示阻断式修改密码页面。

## 数据与审计

新增迁移 `005_admin_rbac.sql`，为 `platform_admin` 增加固定角色列和必要约束，不修改已执行的 `004`。管理员创建、启停、角色调整、密码重置和本人改密均写入 `platform_audit`。

## 验证

覆盖角色权限、最后一个超级管理员、自操作限制、一次性临时密码、强制改密和前端按角色展示；最后统一执行服务端测试、类型检查以及 Web 测试。
