# MOONDROP 开发者门户信息架构调整

## 目标

OIDC 平台对外只作为 MOONDROP 开发者开放平台。公开访问者看到开发者注册、登录、平台能力和接入文档；登录后进入统一开发者控制台，管理开发者个人资料、审核状态、应用和应用组。

开发者账号是平台唯一业务身份。邮箱密码和水月雨账号只是两种登录凭据：邮箱注册直接创建开发者账号；水月雨账号首次登录创建或安全绑定开发者账号。所有开发者资料、审核状态和资源归属继续存储在 OIDC 平台 PostgreSQL，不写入水月雨用户库。

## 页面与路由

- `/`：开发者开放平台首页，包含平台能力、接入流程、支持的应用类型、审核流程、文档导航、注册和登录入口。
- `/developer`：重定向到 `/`，避免维护两套公开门户。
- `/developer/login`、`/developer/register`、`/developer/bind`：开发者认证流程。
- `/developer/docs`：公开接入文档首页。
- `/developer/console/*`：登录后的开发者控制台，包含概览、个人资料、开发者认证、应用、应用组和安全设置。
- `/admin/*`：管理员专用地址，不出现在任何公开导航、首页卡片、页脚或开发者文档中；后续可迁移到独立管理域名。
- `/account/*`：取消前端页面和公开路由。普通 OIDC 最终用户的授权查询、撤销等后端能力暂时保留，避免破坏已有协议能力。

## 首页与文档内容

首页参考成熟开放平台的信息层次，但不复制其视觉或文字：

1. 首屏说明 MOONDROP 登录与标准 OIDC 接入价值，并提供“注册开发者”“登录控制台”“查看文档”。
2. 平台能力介绍标准 OIDC/OAuth 2.0、Authorization Code + PKCE、Web/SPA/Native 客户端、审核与审计。
3. 接入流程展示注册开发者、完善资料并审核、创建应用、配置回调地址、联调上线。
4. 文档导航覆盖快速开始、成为开发者、创建应用、OIDC/OAuth 协议、Web/SPA/Native 接入、API 与错误码、审核规范和常见问题。
5. 首页与文档不展示运营后台、管理员能力或内部审计功能入口。

## 开发者控制台

控制台导航统一为：概览、个人资料、开发者认证、我的应用、应用组、安全设置、接入文档。

- “个人资料”管理开发者显示名称、联系邮箱、联系电话和接入用途。
- “开发者认证”展示未提交、审核中、已通过、已驳回、已禁用状态及审核历史。
- “安全设置”展示邮箱登录凭据和水月雨账号绑定状态；密码修改、解绑和会话管理若后端尚未支持，则先显示明确的未开放状态，不伪造可用操作。

## 安全与兼容性

- 不删除普通 OIDC 用户授权相关后端接口和数据库数据。
- 不改变 `/admin/*` 的鉴权与管理员会话隔离，只隐藏所有公开入口。
- 不自动按邮箱合并水月雨身份与开发者账号；继续使用已实现的显式创建或密码复验绑定流程。
- 公开页面不得请求或渲染开发者、用户或管理员私有数据。

## 实现方案

采用单一公开门户方案：复用现有 React 应用和视觉资产，将 `/` 作为唯一开发者门户，移除并列的账号中心与后台入口。相比保留品牌中转页，这能减少重复页面与身份概念；相比拆分新站点，不引入跨域 Cookie、CORS 和独立发布复杂度。

## 验收标准

- 未登录访问 `/` 时只能看到开发者注册、登录和公开文档相关入口。
- 页面源码、导航、卡片和页脚均不出现 `/admin` 或运营后台入口。
- `/account/*` 不再渲染前端账号中心。
- 水月雨或邮箱登录成功后进入同一开发者控制台。
- `/developer/docs` 无需登录且不请求私有会话 API。
- 现有管理员直接地址和 OIDC 用户授权后端能力不受影响。
