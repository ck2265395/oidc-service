# MOONDROP 开发者账号与资质审核设计

## 1. 目标与背景

MOONDROP 开放平台需要把公开门户和开发者控制台分开。未登录访客只看到平台能力、接入流程、文档及注册/登录入口；完成认证的开发者才能进入控制台。

开发者账号是 OIDC 平台自己的独立身份主体，数据存放在 OIDC 平台 PostgreSQL，不写入 `moondrop-service` 用户库。开发者既可使用邮箱验证码加密码注册和登录，也可使用现有水月雨账号登录并创建或绑定开发者身份。两种登录方式最终访问同一份开发者资料、审核状态和应用数据。

开发者注册后不能立即创建应用。开发者须完善资料、主动提交资质审核，由管理员批准后才能创建应用及应用组。

## 2. 目标

- 提供面向访客的开发者门户和功能介绍，不向未登录用户展示控制台框架。
- 支持邮箱验证码、邮箱和密码注册独立开发者账号。
- 支持邮箱和密码登录开发者控制台。
- 支持水月雨账号登录；首次登录时创建新开发者身份或安全绑定已有开发者账号。
- 支持查看和编辑开发者基本资料，展示明确的开发者审核状态及驳回原因。
- 支持开发者手动提交、重新提交资质审核。
- 只有审核通过的开发者可以创建应用和应用组。
- 提供管理员开发者审核列表、详情、批准、驳回和禁用能力。
- 保留现有开发者资料和应用归属，平滑迁移已有数据。
- 所有注册、登录、绑定、审核及关键权限拒绝均可审计。

## 3. 非目标

- 本阶段不支持手机号验证码注册或登录。
- 本阶段不写入或修改 `moondrop-service` 的普通用户账号。
- 本阶段不做企业认证、营业执照或实名证件审核。
- 本阶段不增加微信、QQ 等其他第三方登录。
- 本阶段不允许管理员代替开发者创建应用。
- 开发者资质审核不替代现有应用和应用组审核；三者仍是独立流程。

## 4. 约束与安全底线

- 水月雨用户库继续作为只读外部身份源。
- 不根据相同邮箱静默合并账号。绑定已有开发者账号时必须再次验证开发者密码或邮箱验证码。
- 密码只保存带独立盐值的强哈希，使用 Node.js 原生 `scrypt`，不新增密码库依赖。
- 邮箱验证码只在 Redis 保存摘要和短期状态，不保存明文；验证码有效期 10 分钟且只能消费一次。
- 注册、验证码发送和登录均按邮箱及 IP 限流；登录错误不暴露邮箱是否存在。
- 开发者会话使用随机高熵令牌，浏览器仅持有 `HttpOnly`、`SameSite=Lax`、生产环境 `Secure` Cookie；数据库只保存令牌 SHA-256 摘要。
- 会话采用 7 天滑动过期并设置 30 天绝对上限。修改密码、禁用账号或管理员撤销会话时立即失效。
- 所有写接口继续执行同源校验和 CSRF 校验。
- 服务将以 PM2 cluster 运行，认证状态不得保存在进程内存中。

## 5. 方案选择

### 已选方案：独立开发者主体 + 多登录身份

`developer_account` 是唯一业务主体；密码凭据和水月雨账号绑定只是登录身份。开发者资料、审核状态、应用组和应用都归属于开发者主体 UUID。

此方案使认证方式与业务所有权解耦，能避免同一开发者因不同登录方式产生两套应用，也便于未来增加企业 SSO 等身份源。

### 未选方案：两种登录方式各自创建开发者空间

实现较少，但会产生重复开发者、重复应用和困难的数据合并，不满足账号绑定需求。

### 未选方案：把开发者注册并入现有水月雨/OIDC 普通用户账号

能复用部分会话，但会要求写入普通用户域，并混淆终端用户和开放平台开发者的生命周期，不符合独立认证域要求。

## 6. 身份与数据模型

### 6.1 `developer_account`

- `id uuid`：开发者主体 ID。
- `status`：`unsubmitted | pending | approved | rejected | disabled`。
- `revision bigint`：乐观锁版本。
- `last_review jsonb`：最近审核动作、原因、审核人和时间。
- `submitted_at / approved_at / created_at / updated_at`。

状态含义：

- `unsubmitted`：已注册或已通过水月雨登录创建身份，但尚未提交审核。
- `pending`：已提交，等待管理员审核；资料在此状态下只读，避免审核内容漂移。
- `approved`：资质有效，可以创建应用和应用组。
- `rejected`：显示驳回原因；编辑资料后可重新提交。
- `disabled`：平台停用；会话失效，禁止进入受保护控制台和操作资源。

### 6.2 `developer_password_credential`

- `developer_id uuid unique`。
- `email_normalized text unique`：去除首尾空白并小写后的登录邮箱。
- `email_display text`：用于页面展示的邮箱。
- `password_hash / password_salt / password_params`。
- `password_changed_at / created_at / updated_at`。

邮箱凭据是可选的：仅通过水月雨账号创建的开发者可以暂时没有密码凭据，之后可在安全设置中补充邮箱登录方式。

### 6.3 `developer_external_identity`

- `id uuid`。
- `developer_id uuid`。
- `provider`：当前固定为 `moondrop`。
- `subject`：水月雨账号 UUID。
- `created_at / last_login_at`。
- 唯一约束：`(provider, subject)`，一个水月雨账号只能绑定一个开发者主体。

一个开发者主体本阶段最多绑定一个水月雨账号。解绑必须保证账号仍有邮箱密码凭据，避免把自己锁在账号外。

### 6.4 `developer_profile`

现有表从以水月雨 `account_uuid` 为主键调整为以 `developer_id` 为主键，字段至少包括：

- 开发者显示名称。
- 联系邮箱及验证状态。
- 联系电话（可选资料字段，仅展示和联系，不发送短信、不作为登录凭据）。
- 开发者类型：本阶段固定支持个人开发者，字段为未来企业开发者预留。
- 简介或接入用途。
- 乐观锁版本及时间字段。

提交审核要求显示名称、已验证联系邮箱和接入用途完整。邮箱注册时的已验证邮箱可直接作为联系邮箱并标记已验证；之后修改联系邮箱需要重新验证。

### 6.5 审核历史与会话

- `developer_review_history`：每次提交、批准、驳回、禁用、恢复的不可变记录。
- `developer_session`：会话摘要、开发者 ID、创建时间、最后活动时间、绝对过期时间及撤销时间。
- Redis 保存邮箱验证码、验证码限流和短周期登录限流，不作为开发者资料或审核状态的唯一存储。

### 6.6 应用所有权

`application_group.owner_account_uuid`、`oidc_application.owner_account_uuid` 的值迁移为 `developer_account.id`。为降低一次迁移风险，第一阶段保留现有列名但在代码中统一称为 `developerId`；后续独立迁移再重命名物理列。

## 7. 用户流程

### 7.1 公开门户

- `/developer`：开放平台门户，展示平台能力、接入步骤、安全能力和常见问题。
- `/developer/docs`：公开接入文档，无需登录。
- 门户提供“注册开发者”和“登录控制台”入口。
- 未登录访问 `/developer/console/*` 时跳转登录页，并保留安全的站内返回地址。

### 7.2 邮箱注册

1. 输入邮箱并获取 6 位数字验证码。
2. 邮件发送成功后进入验证码及密码填写步骤。
3. 校验验证码、密码强度、服务条款确认及限流状态。
4. 在单个数据库事务中创建 `developer_account(unsubmitted)`、密码凭据和基础资料。
5. 创建开发者会话，进入资料完善页。

重复邮箱返回通用提示，并引导登录或找回密码，不泄露更多账号信息。

### 7.3 邮箱登录

- 使用邮箱和密码登录。
- 密码比较采用恒定时间路径；无论邮箱是否存在均执行等价哈希工作。
- `disabled` 账号不建立会话，并显示联系平台管理员的通用提示。

### 7.4 水月雨账号登录

1. 用户从开发者登录页选择“使用水月雨账号登录”。
2. 复用当前 OIDC 授权流程验证水月雨账号，不接触其密码。
3. 若 `(moondrop, account_uuid)` 已绑定，建立对应开发者会话。
4. 若未绑定，进入选择页：
   - 创建新的开发者身份：建立 `developer_account(unsubmitted)` 和外部身份绑定，再完善资料。
   - 绑定已有开发者账号：通过开发者密码或发送到该开发者邮箱的验证码完成二次验证，再创建绑定。
5. 不因两个账号邮箱相同而自动绑定。

### 7.5 资料与资质审核

1. `unsubmitted` 或 `rejected` 开发者可以编辑资料。
2. 页面顶部以明显状态卡展示状态、最近提交时间和驳回/停用原因。
3. 资料满足要求后，开发者点击“提交审核”并确认。
4. 状态变为 `pending`，管理员后台出现待审记录。
5. 管理员批准后状态变为 `approved`；驳回后变为 `rejected` 并要求填写原因。
6. 被驳回开发者修改资料后可再次提交；每次审核均保留历史快照。
7. 管理员禁用开发者时撤销其所有会话，并禁止其应用管理操作；已上线客户端是否同步停用作为显式管理动作，不自动级联，避免生产事故。

### 7.6 应用权限

- 后端是最终权限边界：所有创建应用和应用组的接口必须检查开发者状态为 `approved`。
- 前端同时禁用创建入口并显示原因，但不能替代后端校验。
- 未审核开发者仍可查看公开文档及自己的资料、状态和审核历史。
- 已有应用的查看、编辑、密钥轮换等管理操作要求开发者账号未被禁用；创建新资源额外要求 `approved`。

## 8. 页面结构

### 8.1 未登录页面

- 开放平台首页：MOONDROP 品牌、能力介绍、接入流程、协议能力、注册与登录 CTA。
- 开发者注册页：邮箱验证、密码设置、协议确认。
- 开发者登录页：邮箱密码表单和“使用水月雨账号登录”。
- 账号绑定选择页：创建身份或绑定已有开发者账号。
- 公开接入文档。

### 8.2 登录后控制台

- 概览：开发者状态卡、资料完成度、应用统计和待处理事项。
- 开发者资料：查看和编辑基本资料、验证联系邮箱、提交审核。
- 我的应用：仅审核通过后开放创建入口，展示应用审核状态。
- 应用组：仅审核通过后开放创建入口。
- 账号与安全：邮箱登录方式、水月雨绑定状态、密码修改、会话退出。
- 接入文档。

### 8.3 管理后台

- 新增“开发者审核”菜单。
- 列表支持按状态筛选，显示开发者名称、邮箱、登录身份类型、提交时间和历史审核次数。
- 详情展示本次提交的资料快照及历史记录。
- 支持批准、驳回、禁用和恢复；驳回、禁用必须填写原因。

## 9. 接口边界

新增接口按职责拆分：

- `/api/v1/developer-auth/*`：验证码、注册、邮箱登录、水月雨回调后的绑定、登出和当前开发者会话。
- `/api/v1/developer/*`：资料、审核提交、审核历史、应用和应用组管理。
- `/api/v1/admin/developers/*`：管理员开发者列表、详情和审核动作。

关键接口包括：

- `POST /api/v1/developer-auth/email-code`
- `POST /api/v1/developer-auth/register`
- `POST /api/v1/developer-auth/login`
- `POST /api/v1/developer-auth/logout`
- `GET /api/v1/developer-auth/session`
- `POST /api/v1/developer-auth/moondrop/start`
- `POST /api/v1/developer-auth/moondrop/create`
- `POST /api/v1/developer-auth/moondrop/bind`
- `GET/PUT /api/v1/developer/profile`
- `POST /api/v1/developer/review/submit`
- `GET /api/v1/developer/review/history`
- `GET /api/v1/admin/developers`
- `GET /api/v1/admin/developers/:id`
- `POST /api/v1/admin/developers/:id/review`

接口保持当前 JSON 结构 `{code, desc, data}`。错误码明确区分未登录、资料不完整、审核中、未通过审核、已禁用、版本冲突和限流，但登录错误不区分邮箱不存在与密码错误。

## 10. 迁移策略

1. 新增一份顺序迁移脚本和同步后的 `sql/postgre.sql`。
2. 为每条现有 `developer_profile.account_uuid` 创建一个 `developer_account`：
   - 已有开发者默认迁移为 `approved`，避免升级后突然失去应用管理权限。
   - 建立 `(moondrop, account_uuid)` 外部身份绑定。
   - 保留资料邮箱验证状态。
3. 把现有应用及应用组的 owner 值从水月雨账号 UUID 更新为对应开发者 UUID。
4. 没有开发者资料但存在孤立应用所有者时，也创建已批准的兼容开发者主体和外部身份绑定，并记录迁移审计。
5. 迁移需要可重复执行；更新所有权前后校验开发者、应用、应用组数量以及不存在无映射 owner。
6. 发布期间先部署兼容读取代码，再执行迁移，最后启用新认证入口；不在迁移窗口删除旧列或旧代码路径。

## 11. 错误处理与一致性

- 注册、绑定和提交审核使用数据库事务与唯一约束处理并发。
- 状态修改使用 `revision` 乐观锁，冲突返回 409 并要求刷新。
- 邮件发送失败不得创建半成品注册账号；验证码可重新申请但受限流控制。
- 水月雨授权成功但绑定步骤未完成时只保存短期、一次性的绑定上下文，不创建长期开发者会话。
- 管理员审核时保存资料快照，确保以后能还原当时审核的内容。
- 应用创建权限在 service 层统一判断，避免新增接口绕过 controller 校验。

## 12. 测试与验收

- 单元测试：邮箱规范化、密码哈希、验证码消费、状态机、权限判断、绑定冲突和乐观锁。
- API 测试：邮箱注册/登录、错误凭据、限流、CSRF、登出、会话过期、水月雨首次登录、绑定已有账号、重复绑定。
- 审核测试：资料不完整不能提交、提交后锁定、批准/驳回/重提、禁用撤销会话、未批准不能创建应用。
- 迁移测试：已有资料、孤立 owner、重复执行、数量核对和回滚前置检查。
- 前端测试：未登录只显示门户；注册和双登录入口；状态卡；创建按钮权限；管理员审核流程。
- 安全测试：账号枚举、验证码重放、会话固定、绑定劫持、跨站请求和开放跳转。
- 全量执行 TypeScript、ESLint、服务端测试、Web 测试和生产构建。

验收标准：未登录访客无法看到或调用控制台私有数据；两种登录方式可安全归并到同一开发者主体；开发者状态在页面清晰可见；未获批准的开发者无法通过任何接口创建应用；已有开发者及其应用在迁移后仍可通过水月雨账号访问。

## 13. 实施者可自行决定的细节

- 门户文案、卡片数量和非关键视觉动效可沿用现有 MOONDROP 设计系统调整。
- 6 位验证码邮件的具体排版与主题可复用现有 SMTP 配置。
- 联系电话作为可选资料字段，不进行短信验证。
- 第一阶段保留现有 owner 物理列名，代码层完成语义转换，降低迁移风险。
